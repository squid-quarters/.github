# Squid Quarters review and integration

This is the shared process source for Squid Quarters personal projects, including Paperclip work. Repository-specific checks, architecture, design approvals and working-directory constraints still apply. This file does not grant tool access or change security settings.

1. **Integrate through a PR.** Code, design, docs and workflow changes all land remotely through a scoped PR targeting the repository's actual canonical branch. Never push directly to canonical or release branches. Preserve user edits and concurrent work; use the project's isolated-worktree rules, including its explicit Unity single-writer exception.
2. **Review substantively and independently.** AI review is accepted. Give reviewers the task's acceptance criteria, base/head and relevant source context. Use adversarial, relevant lenses: behavior, regressions, trust boundaries, races, failure paths and test gaps for code; usability/accessibility, voice, source accuracy, consistency, provenance and real workflow consequences for design/docs. Scale the depth to impact, not line count. CI green, lint, self-review and a cursory skim alone do not satisfy review.
3. **Keep findings high-signal.** Require concrete evidence and impact; deduplicate and prioritize high-confidence material findings. Do not invent nits to fill a quota. Fix material findings in the same PR; record reasoned dispositions for rejected findings. Repeat independent review of the final diff until no material findings remain unresolved.
4. **Verify the final change.** After fixes, run all applicable configured deterministic checks/tests and exercise changed behavior with realistic adversarial cases. Inspect relevant design renders and browser/UI flows; validate docs against their sources and actual loading paths. Missing required checks or independent review blocks merge. Record the reviewed head SHA, reviewer findings/dispositions, check commands/results, functional/visual evidence and limitations on the PR. Ensure the current PR head still matches the reviewed/tested head before merge; a changed head needs renewed relevant review and verification.
5. **Autonomy stays scoped.** Agents may independently review, fix, test and merge an authorized task's PR once requirements and required forge checks pass. Inspect merge-triggered publishing before merging. Deployments, credentials, production-data changes and persistent access/security changes need separate task authority; a reviewed PR does not grant that authority. Preserve existing proprietor/client design decision approvals.

## Loading this process

GitHub does not automatically distribute this repository's AGENTS.md or this file to other repositories. A project must explicitly adopt the process in its instruction entry point. Claude's @ import and Codex's AGENTS.md discovery are different mechanisms; changing one file does not wire another tool.

For the local Paperclip Squid Quarters company, the existing role AGENTS.md files direct agents to PERSONAL.md, which directs them to the personal CHARTER.txt. The charter's repository workflow should direct agents to the merged checkout's REVIEW.md before review or integration, alongside applicable project instructions. Deploy this content only after its reviewed PR merges; do not change agent adapters, credentials, permissions, assignments, timers or the separate ST Engineering company. A control-directory run must explicitly read the assigned repository's instructions; an unrelated control cwd does not auto-load project guidance. Existing runs need to read the updated instructions before relying on them.
